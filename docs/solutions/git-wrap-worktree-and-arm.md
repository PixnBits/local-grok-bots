# Git wrapper: physical worktree, arming, and config values

`core.worktree` is resolved with `cd -P` from the directory that holds the config file. The check refuses when that physical path is outside `/work`. `../inner` and a `.git` symlink or gitfile whose git directory stays inside still pass.

Removal forms (`--unset`, `--unset-all`, `--remove-section`, `config unset`, `config remove-section`) do not use `git -C` on the work tree. The git directory is found from the filesystem, then git runs with `--git-dir` and `--work-tree` set to that directory. A relative `core.worktree` that does not exist otherwise makes git exit with "cannot chdir" before the key can be removed. Other writes still go through `config_guard`.

The file protocol is armed only from the repository positional the command uses (`vet` / `accept_local`). `scan_urls`, skipped option values, and `vet_opt` use a check that does not arm. A sibling remote that a no-argument `fetch` or `pull` only checks does not arm. `fetch --all`, `remote update`, and named `remote prune`, `update`, and `show` vet every remote they contact and may arm. A slashless name that exists as a path beside the command, including a symlink, is vetted as a local path. A configured remote name is the stored URL, not a directory of the same name. For `git config`, the file scan runs after `config_guard`, so a refused key is named instead of reported as an outside path. `git submodule add` exports `GIT_ALLOW_PROTOCOL=file` only when that command's URL positional is a vetted file URL: the nested clone does not keep `protocol.file.allow=user`. `update`, `init`, `sync`, `foreach`, and `status` do not export it and keep `protocol.file.allow=never`.

`branch.*.remote` and `branch.*.pushremote` are `.` or the name of a configured remote. `remote.*.tagopt` is exactly `--no-tags` or `--tags`. `pack.threads` is an integer from 0 to 256 with at most three digits. `submodule.*.url`, `help.autocorrect`, `commit.gpgsign`, and `pack.threads` share `config_value_allowed` in the scan and in `config_guard`. A relative `submodule.*.url` must stay inside `/work` lexically and physically. Before `submodule update`, `init`, or `sync`, `.gitmodules` (a regular file, not a symlink) and stored `submodule.*.url` values are vetted. A relative URL is resolved against `remote.origin.url`. An outside path, an unlisted URL, or an empty origin is refused before git writes the key. Nested `.gitmodules` inside a submodule is reachable only over an allowlisted https URL through the bridge. The scan probes with a single SOH byte; a restricted key then reads every `--null --get-all` value. A newline in a stored value is translated to SOH and refused before the value rule. A newline or tab in a value is refused. With no repository positional, `fetch`, `pull`, and `ls-remote` read the branch with `symbolic-ref HEAD` (not `--short`) and arm that remote, or `origin` when the head is detached or the branch remote is unset. `pushRemote` is checked on those commands and does not arm them. `push` resolves the branch remote and `pushRemote`, and checks `origin` when neither is set.

A `git config` long option is refused unless its name is an exact known form. An abbreviation of `--type` or `--comment` is a write. A value that starts with `-` is still a value once the key is known, including `remote.*.tagopt`. `git init` confines the target directory, `--separate-git-dir`, and `--template` with a physical path check, including a unique-prefix spelling and a path after `--`. When parent directories do not exist yet, the nearest existing ancestor is resolved physically and must stay inside `/work`, and the missing suffix cannot contain `..`.
