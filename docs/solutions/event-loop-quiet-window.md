# Event-loop interim calls stay off the stored transcript

`ollama.event_loop` defaults off. While a `run_shell` call is in flight and the flag is on, user messages only wake a quiet window. The window is armed before the tool goroutine starts, under `rtMu`, and the closure checks run id and loop generation so a stale run cannot notify it.

The quiet timer and the max-wait timer need separate generations. A later wake-up restarts only the quiet timer. Bumping one generation for both lets a stale quiet callback drop the max-wait timer, or fire a window that `Notify` just re-armed.

The interim model call reads a copy. It does not call `MarkRunInput` and does not change `seen` or `through`. `foldInput` on the next real model call appends those user messages after the real tool result. A newer batch cancels only the interim context and publishes `stream_reset` reason `interim_superseded`. When the shell finishes, or the run context is cancelled, the helper still cancels a running interim so the goroutine can be joined. That join is not a supersede: do not publish `interim_superseded`. If that interim had already streamed text, publish `stream_reset` reason `interim_cancelled` so the partial does not run into the final reply. A genuine model error after streamed text publishes `interim_error` instead. A clean finish with text publishes a blank-line separator and no `stream_reset`. One run starts at most 5 interim calls. A batch past that cap is skipped and the in-flight call is left alone. The budget for those starts lives on the bot's loop state, keyed by run id, and is replaced only when the run id changes, so an approval resume of the same run keeps the remaining count. It is memory only. A daemon restart clears it, so approving a restored checkpoint afterwards starts a fresh count, and a continue starts a fresh count because it is a new run id. A nil budget refuses every interim start, writes `event_loop_interim_refused` for the dropped window, and does not write the capped or suppressed rows. A window with no new input is not a skipped batch: it does not log a row and it is not counted. The first skipped batch that has new input logs `event_loop_interim_capped` and is counted; later ones are counted on one `event_loop_interim_capped_suppressed` row when the shell ends, and none of them log `event_loop_batch`. An `event_loop_interim` row stores an error class and a short message. Paths and host names in that message are replaced, and the message is cut to 200 bytes on a UTF-8 boundary. A run deadline during an interim publishes `interim_cancelled`. The cap is not a policy key.

The system prompt's `Current time:` line uses the wall clock, not the injected window clock. Two flag-off runs are not byte-identical until that line is normalized. `holdTurn` snapshots policy when `execute` starts, so a test must publish the flag before the POST that starts the run. These keys are not in the hot-reload subset (voice and `claude_transport` only). A bad duration fail-closes through `Warnings`; a bool of the wrong TOML type names the Go field `EventLoop`.
