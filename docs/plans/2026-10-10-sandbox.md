# Sandbox grants

Target is `docs/sandbox.md`. The default stays a workspace-only jail with no network. A missing grant fails closed.

## Decisions

- `run_shell` uses bubblewrap when `bwrap` is on `PATH`. Otherwise it keeps the unshare + chroot jail, adds a network namespace so there is still no egress, and fails closed if that cannot be set up.
- The unshare jail exposes the entropy devices and not the rest of `/dev`.
- The workspace is bind-mounted at `/work`. The host filesystem outside it is not mounted. The child starts with a cleared environment, so the user agent and host git config are not inherited.
- Writes to `.git/hooks`, shell rc names, `.gitconfig`, and git config that carries an executable setting (`sshCommand`, `hooksPath`, `fsmonitor`, a `!` alias) are blocked. `write_file` rejects them. The shell restores those paths after the command and fails the tool if they changed.
- Grants live on the bot: `net`, `git`, `ssh`, `build`. Empty means none. The profile and `POST`/`PATCH /api/bots` set and clear them, plus `net_allow` and `ssh_allow`. `create_bot` and `update_bot` do not read grant fields.
- `net` sends shell TCP through a proxy outside the jail. The allowlist is exact hostnames, empty by default. A connect to anything else is refused. With the grant, a refused host is logged as `net_request`. Without the grant, the same attempt is `grant_denied`. Loopback inside the jail is not egress.
- `git` allows clone and commit inside the workspace. The jail does not mount `~/.ssh` or the host git config. `git push` does not push. It returns the diff and status, and the thread gets a system line. Token injection is not built.
- `ssh` reaches only hosts on `ssh_allow`, through the same proxy, with a daemon-owned key created under the data dir. The user agent is not mounted. Every allowed connection is logged and shown as a system line on that bot's thread. Port 22 requires this grant even if `net` is set.
- `build` adds read-only binds from `SANDBOX_BUILD_BINDS` (colon-separated absolute paths). Paths that are ssh directories, git config, or shell rc files are refused. Nothing extra is writable. With no grant, or with an empty setting, the mounts stay as they are now.
- Grant use and denial are log events (`grant_use`, `grant_denied`, `net_request`, `sandbox_block`). Irreversible lines use the prefix `Notice:` so they show on the thread and are not treated as scheduled prompts. They do not start a new turn.
- Hide, pin, the menu, and the conversation stay as they are. Duplicate does not copy grants.

## Out

Browser grant, microVMs, a policy language, capability tokens, mounting host credentials, computer-use, channels, templates. Git push tokens. Package-manager installs are not a separate grant; they still need `net` and an allowlisted host.

## Tests

- Paths that leave the workspace are rejected, including the existing jail test.
- No `net` grant: a shell connect fails and is logged as a denial.
- `net` grant: only allowlisted hosts connect; other hosts are logged as requests.
- No `git` grant: push is denied. With `git`: commit works in the worktree; push returns the diff and does not dial.
- No `ssh` grant: no SSH connect. With `ssh`: only the allowlist, and the thread shows the notice.
- Meta tools cannot set grants. Hide still does not pause.
