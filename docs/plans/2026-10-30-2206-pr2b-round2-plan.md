# Permission broker round 2

## Goal

A data directory written by fcc6144 keeps working on this branch: an unchanged git baseline is re-recorded in the new piece set and does not ask. Real drift still asks, with a plain reason. The other review items in this run are server behaviour, goldens, and the CSP asset split.

## In this run

- Old baselines are detected by the piece set (no `system-gitconfig` line), not by the JSON version alone. New files keep version 1 and add format 2. Upgrade runs only when the homes named in the blob match the bot's current homes. A match rewrites the baseline and audits actor `upgrade`. A mismatch still asks. Pending items carry `git_reason`.
- The system gitconfig path is resolved at startup. The package variable stays so tests can point it elsewhere. A symlinked directory that contains `.gitattributes` is a git risk and is not added to the baseline list.
- Non-broker permission writes use the same Origin and Sec-Fetch-Site check as broker posts, and they require a JSON body.
- A task grant matches the raw cwd string and the task id. `ws/` and `ws/./` are different strings from `ws`.
- Deny-all and approve-all take a non-empty id list, skip stale or unknown ids, and return per-item results. An empty body does not deny every bot.
- A command that is not literal can only be approved once.
- Confirming a legacy allow that cannot match returns 400 `never_matches`. Creating an allow whose command is ineligible does the same. A deny of a critical command is stored. The rules list shows `confirmable` and `never_reason`.
- HTML and other responses send the CSP and nosniff headers. Scripts and styles are same-origin files.
- Live allow paths refuse a git risk and a critical level. A classifier raise to high or above makes an existing bot or global allow ask.
- `POST /api/permbroker/rules/{id}/replace` creates the new rule, then revokes the old one. A failed revoke keeps both.

## Out of this run

Focus loss, notification body text, advisory labelling, menu arrows, and the rest of the approvals UI. The Claude session cwd and `run_shell` cwd are recorded, not changed: there is no separate working directory to forward.

## Tests

Each new golden has to fail when its own check is removed. The fcc6144 fixture bytes are written in the test. `ws/` and `ws/./` ask. Empty deny-all is 400. `grep "$(id -u)" a.txt` and `grep A a.*` offer only `once`.
